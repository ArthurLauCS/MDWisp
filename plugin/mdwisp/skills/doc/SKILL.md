# 按文档文件夹格式写文档

把文档写成**自带图片的文件夹**，拷到任何机器上图都还在。

```
我的笔记/
├── 我的笔记.md
└── 我的笔记_img/
    └── 架构草图.svg
```

```markdown
![架构草图](./我的笔记_img/架构草图.svg)
```

- 文件夹名、md 主文件名、`_img` 前缀三者一致。没有图片时不建 `_img`，md 仍放在同名文件夹里。
- 用户指定了位置就建在那里，否则建在当前工作目录下。同名文件夹已存在时不覆盖，问用户换名还是写进去。
- 往**已有的** md 里加图：图片放进它旁边的 `主文件名_img/`，不搬动这份 md。

## 图片模式

判断不出来就按「尽量生成图片」。

- **不生成图片**（用户说「不要图片」「纯文字」「无图」等）：不建 `_img`，不出现图片语法，不留「此处应有图」占位；需要表达的结构改用表格、列表或代码块里的字符图。
- **尽量生成图片**（默认）：流程、架构、层级、时序、状态、对比、数据、界面布局等图比文字清楚的地方都配图。每张图说明一件文字说不清的事，不配装饰图。

| 图的性质 | 做法 |
| :--- | :--- |
| 结构、流程、关系、示意（绝大多数） | 手写 SVG |
| 数据图表 | 脚本用绘图库生成 SVG/PNG，只把图片存进 `_img`，脚本不留在文档文件夹 |
| 真实界面、运行结果 | 能运行且有截图工具就截图存 PNG；否则画 SVG 线框图并在图注注明是示意 |
| 照片、插画 | 有图像生成工具就生成并存文件；没有就不配，交付时说明缺什么图 |

拿不准就先用 SVG 表达意思，交付时说明可以换成什么。只描述不画不算配图。

## 禁止

1. 绝对路径：`C:\...`、`/home/...`、`file:///...` 不出现在图片引用里。
2. base64 内嵌图片，除非用户明确要求（并说明是例外）。
3. 把自己生成的图片上传到图床或任何第三方服务。引用已有网络图片可以，但它可能失效。

## 路径与命名

- 路径以 `./` 开头，分隔符一律 `/`，原样书写不做 URL 编码。
- 文件名是「内容语义 + 扩展名」，可用中文，如 `登录流程.svg`；不要 `image1.png`。不含空格、括号和 `# ? % : * " < > |`，分隔用 `-`。
- 同名文件已存在：内容相同复用，不同加后缀 `架构图-2.svg`；未经用户同意不覆盖。
- 每张图写说清含义的 alt 文字。

## SVG

写 `viewBox` 和固定宽高；`font-family` 以 CJK 字体收尾（`'PingFang SC', 'Microsoft YaHei UI', 'Noto Sans SC', sans-serif`）；不引用外部资源（图片、字体、`@import`）；标签短、框宽留足；背景用实色。

## 写作

可选 YAML front matter（`title`、`tags`）；一个 `#` 一级标题，层级不跳级；代码块写语言标记。代码块和行内代码里的图片语法是示例，不需要对应文件。

## 交付前校验

```bash
node scripts/check.mjs "<文档文件夹或 md 文件>"
```

不生成图片模式加 `--no-images`。脚本检查目录结构、图片路径相对且存在、`_img` 里无未引用文件、SVG 自包含；修到通过再交付。交付时告诉用户文件夹路径、图片数量、哪张图因缺工具没配上。
