# 导出可分享的单文件文档

把带本地图片的 markdown 整理成**单独发出去就能读**的一份，不损坏原文。

## 规则

**删除**（别人机器上打不开的）：指向本地文件的图片引用（`![图](./笔记_img/a.svg)`）、HTML 媒体里的本地路径（`<img src="file:///C:/...">`）、指向本地文件的链接（`[笔记](./另一篇.md)`）、front matter 里的编辑器私有字段（如 `mdview:`）。

**保留**：远程图片、`data:` 内嵌图片、远程链接与锚点链接、其余所有正文、列表、表格、引用。

**绝不触碰**：围栏代码块（反引号与波浪线分别配对，含四个反引号的长围栏）和行内代码里的内容——那里的图片语法是给人看的示例。

## 图片怎么处理，先问用户

1. **丢弃**：删掉整条图片引用，正文保持连贯。
2. **留占位**：保留 alt 文字，如 `![架构草图](图片已移除)` 或 `> [图：架构草图]`。

用户没说就按项目设置；也没有设置就留占位，并在交付时说明。

## 先预览，再写出

写出前逐条列出将删除的行：行号、原文、原因，用户确认后再输出。不要用「已清理若干处」之类的含糊说法。

## 保持原样

逐行处理，只改需要改的行；不要用解析器重新渲染整篇（会改格式和列表符号）；不动空行、缩进和表格竖线对齐；不加「本文档由 XX 导出」之类的说明。

## 交付前自查

1. 代码块内容与原文逐字一致。
2. 每条删除都说得出原因。
3. 代码示例之外不剩绝对路径、盘符、`file://`。
4. 保留的远程链接与 `data:` 图片未被改动。
